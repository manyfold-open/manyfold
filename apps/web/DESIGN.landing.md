# Landing 视觉系统 — Iris / Fieldwork / Serif

这份文档只管 **landing（营销页）** 这一个语域。它是自足的：实现 landing 不需要先读 `DESIGN.md`。

三条支柱，一句话各一条：

- **色彩** —— 中性底 + 单支强调色。纸是真中性的，所有颜色预算花在 Iris 一支蓝上。
- **装饰** —— Fieldwork：凡是被画出来的东西都量化到格子上，字形承担墨阶，12 秒无缝循环。
- **文字** —— 两个语域：细衬线（Fraunces SOFT 50）说话，无衬线（Geist）干活。

怎么读这份文档：

- **要动手改**：§10 落地清单 → 每一项都指回对应章节。
- **要判断一个做法对不对**：§9.4 Do / Don't，然后是 §3.4（场的七条法则）与 §2.6（字的六条规则）。
- **要确认某个场景不会崩**：§8 场景矩阵。
- **要加新东西**：§9.2 的门槛表。
- **要知道数学在哪**：§3.6 —— 代码是规范，散文只解释 why。

视觉参考实现：仓库根的 `.landing-iris-field-serif.preview.html`（自带 light/dark 切换与 `?theme=&frame=&total=` 定格参数）。本文档与该 mock 冲突时，**以本文档为准**；mock 在 P1 挂载完成后应当删除（§3.7）。

## 0. 范围与边界

### 0.1 本文档管什么

`.landing-root` 作用域内的一切：`--lp-*` token、249 个 `.lp-*` 类、marketing nav/footer、以及新增的 Fieldwork 组件。

### 0.2 本文档不管什么

**产品语域（webapp + docs）在本轮完全不动。** `:root` 上的 `--color-*` 保持石墨灰蓝，产品的 32/22/20/18 字号阶梯、8/10/14 圆角上限、500 字重上限全部照旧。理由是范围控制，不是这套系统只适用于 landing —— 后续把它推到 webapp 与 docs 时，需要各自一份迁移文档（见 §12）。

**两个语域会在一段时间内并存**，这是可接受的中间状态：`--lp-*` 是 `.landing-root` 的局部变量（`styles.css:1988`），不会漏进 app shell。

### 0.3 改动落在哪个仓库

landing 的真身在 `oss/`（公共仓库 `manyfold-open/manyfold`）。按 `AGENTS.md`：**核心改动不在父仓落地**，要在 `oss/` 内开分支推到公共仓库、发 PR；oss-bump 机器人再把 submodule 指针 PR 回父仓。本文档本身也是核心文件，随同一个 PR 走。

### 0.5 一个未决问题：hero 到底长什么样

**这是本轮唯一需要你先拍板的结构问题，其余都已定。**

三个选项：

| 选项                                  | 代价                                                                                                                                            |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. 保留翻面卡，只换配色与字体**     | 最小改动。`FloorHero` 的 700 字重换成衬线 300，翻面动效不动。Fieldwork 只作为大气层与分区插图出现，hero 里没有主体场                            |

## 1. 色彩系统

### 1.1 总原则：中性底 + 单支强调色

颜色预算全部花在 Iris 一支上，**底色、边线、投影一律保持中性**。这也是 Linear / Vercel 那一类工具型产品的做法。

底色染主题色的代价有两个，都难以逆转：强调色在自己的浅色版本上失去对比；整站蒙一层洗不掉的"滤镜感"。

纸感不靠染色，靠 **近白的明度 + 极窄的层级差**：画布 244 / 卡面 252 / 抬升 255，加一条 1px 边。

### 1.2 中性轴 Ash

只留 2–4 单位的冷偏（B 略高于 R），用来抵消暖色屏上的发黄，肉眼读不出色相。

| 层级         | `--lp-*` token    | 浅色      | 深色      | 用途                     |
| ------------ | ----------------- | --------- | --------- | ------------------------ |
| canvas-sunk  | `--lp-bg-deep`    | `#e7e8ea` | `#050506` | 下沉带、footer           |
| canvas       | `--lp-bg`         | `#f4f4f6` | `#0a0a0c` | 页面画布                 |
| canvas-soft  | `--lp-bg-soft`    | `#f9f9fb` | `#101013` | 交替分区、小 hover 填充  |
| paper        | `--lp-paper`      | `#fcfcfd` | `#161719` | 卡面                     |
| paper-raised | `--lp-paper-warm` | `#ffffff` | `#1e1f23` | 抬升卡面、popover        |
| ink-1        | `--lp-ink`        | `#101013` | `#ededef` | 标题、正文主色           |
| ink-2        | `--lp-ink-soft`   | `#2a2b30` | `#c6c7cb` | 引导段 lead              |
| ink-3        | `--lp-muted`      | `#5c5e66` | `#8c8e96` | 次级正文                 |

### 1.3 品牌轴 Iris

色相 **≈226°**（鸢尾蓝：带一点紫的皇家蓝）。三轮定下来的：247° → 235° → 226°。离旧的钢蓝 `#3b82c9`（210°）还有 16°，而且明度低得多、彩度高得多，不会读成同一支。

**彩度按 OKLCH 校准，不按 HSL 猜。** 主色的 OKLCH 彩度 **C = 0.215**，正好是 Tailwind blue-600 / Vercel blue 那一档 —— 这是"明确是个颜色"与"荧光"之间的那条线。整条 ramp 的 C 走一条弧、在 700 附近最高（C 0.231），因为蓝色的最大可用彩度本来就落在 L≈0.47 一带；硬要在 600 的明度上榨彩度只会掉出色域。

| 档位 | hex       | OKLCH L / C   | 用途                                   |
| ---- | --------- | ------------- | -------------------------------------- |
| 50   | `#edf1ff` | 0.959 / 0.019 | 最浅底纹                               |
| 100  | `#dbe3ff` | 0.918 / 0.039 | 选中态底、tag 底                       |
| 200  | `#b9c8fd` | 0.840 / 0.076 | 深色模式场的最亮墨                     |
| 300  | `#8ca5f9` | 0.737 / 0.125 | 深色模式深墨版、头像堆叠               |
| 400  | `#5d80f4` | 0.632 / 0.178 | **深色模式主色**、深色模式场中墨       |
| 500  | `#426bf0` | 0.576 / 0.205 | 场的中调                               |
| 600  | `#3560eb` | 0.546 / 0.215 | **浅色模式主色**、场中墨               |
| 700  | `#1842d8` | 0.466 / 0.231 | **浅色模式深墨版**、按压态、链接 hover |
| 800  | `#1833a0` | 0.384 / 0.178 | 深色文字                               |
| 900  | `#152466` | 0.295 / 0.117 | 浅色底上的最深文字                     |

**整条 ramp 本身就是 token**，其余全部从它派生。不要只暴露 info/info-bg/info-strong —— 定价卡的环、深底上的焦点环都需要 300 这一档，不开出来就会有人写裸十六进制。

`rgb` 三元组一律**空格分隔**，与产品的 `--color-*` 同一约定，配现代 `rgb(… / α)` 语法。混用逗号分隔会让 `rgb(var(--x) / .3)` 静默失效。

```css
/* 十档全开（两个模式共用同一组档位值，只有语义别名的指向不同），
   另外给四个会被 alpha 用到的档位配 rgb 三元组。 */
--lp-iris-50: #edf1ff;
--lp-iris-100: #dbe3ff;
--lp-iris-200: #b9c8fd;
--lp-iris-300: #8ca5f9;
--lp-iris-300-rgb: 140 165 249;
--lp-iris-400: #5d80f4;
--lp-iris-400-rgb: 93 128 244;
--lp-iris-500: #426bf0;
--lp-iris-600: #3560eb;
--lp-iris-600-rgb: 53 96 235;
--lp-iris-700: #1842d8;
--lp-iris-700-rgb: 24 66 216;
--lp-iris-800: #1833a0;
--lp-iris-900: #152466;

/* 语义别名 */
--lp-info: var(--lp-iris-600); /* = 品牌色，与 info 状态色合并成一支 */
--lp-info-bg: rgb(var(--lp-iris-600-rgb) / 0.1);
--lp-info-strong: var(--lp-iris-700);
--lp-focus-rgb: var(--lp-iris-600-rgb);

/* Fieldwork 的墨色单独别名：现在与品牌色同值，但会分开演化（§9.1 第 3 条） */
--lp-field: var(--lp-iris-600-rgb);
--lp-field-deep: var(--lp-iris-700-rgb);

/* 深色：档位值不变，只有语义别名整体上移一档 */
--lp-info: var(--lp-iris-400);
--lp-info-bg: rgb(var(--lp-iris-400-rgb) / 0.16);
--lp-info-strong: var(--lp-iris-300);
--lp-focus-rgb: var(--lp-iris-400-rgb);
--lp-field: var(--lp-iris-400-rgb);
--lp-field-deep: var(--lp-iris-300-rgb);
```

**品牌色与 info 状态色是同一支，不再分两个值。** 参考图就是这么干的，也少一个要维护的蓝。

对比度：600 在 `#f4f4f6` 上 **4.75:1**，在纯白上 5.22:1 —— 小字用色也过 AA。深色模式 400 在 `#0a0a0c` 上 5.52:1。

### 1.4 判定色

四支，各有分工。值不变（本轮不动），但要知道为什么它们的彩度低于 Iris：品牌色本来就该是画面上彩度最高的一支，而且绿和黄在同等彩度下会直接变荧光。实测 C 0.14–0.20，与 Iris 的 0.215 是正确的关系。

| 角色                  | token          | 浅色 fill / text      | 深色      |
| --------------------- | -------------- | --------------------- | --------- |
| Jade · 成功 / 已交付  | `--lp-success` | `#22c46f` / `#12a75c` | `#3bd383` |
| Amber · 排队 / 待处理 | `--lp-warning` | `#e9a23b` / `#c8811c` | `#efb45e` |
| Coral · 失败 / 破坏性 | `--lp-error`   | `#f2554b` / `#dd3d34` | `#ff7a70` |
| Idle · 空闲 / 禁用    | `--lp-idle`    | `#9a9db2`             | `#6d7085` |

**一支色两个亮度**（参考图里最值得抄的细节）：计量条的填充用饱和的 500，旁边的读数用更浅的 400，标签退到 ink-3。写成规则：

```
fill = 500 · numeral = 400 · label = ink-3
```

数据的"量"由饱和度承担、"读数"退一档，一排计量条才不会变成一片绿噪声。注意这是**知情的低对比选择**：`--lp-success` 的 400 档在浅色底上约 2.9:1，不满足正文 AA —— 它只允许出现在紧邻实心填充条的读数上，那根条本身就是非颜色信号。**不要**把这个亮度用于任何独立的文字。

### 1.5 阴影：拆掉铣削铝

现在的 `--lp-shadow-*` 是"铣削铝"配方：顶部白色内高光 + 铂金色底部内发光 + 紫黑外投影，共 7 个 token × 2 个模式（`styles.css:2086` 与 `:2210`）。

**全部换成：1px 边 + 单层扩散投影。** 两个理由：

1. 参考图的卡片是"纸叠在纸上"，金属质感会和像素场直接打架 —— 两种都在争夺"这是什么材质"的解释权。
2. 顶部白色内高光在近白纸（244–255）上根本无处发光，只会让卡面边缘发灰。

```css
/* 浅色 */
--lp-shadow-sm:
    0 1px 0 rgba(14, 14, 20, 0.03), 0 4px 10px -6px rgba(14, 14, 20, 0.16),
    0 0 0 1px var(--lp-line-soft);
--lp-shadow-md:
    0 1px 0 rgba(14, 14, 20, 0.04), 0 10px 26px -14px rgba(14, 14, 20, 0.2),
    0 0 0 1px var(--lp-line-soft);
--lp-shadow-lg:
    0 1px 0 rgba(14, 14, 20, 0.05), 0 20px 48px -24px rgba(14, 14, 20, 0.24),
    0 44px 80px -60px rgba(14, 14, 20, 0.3), 0 0 0 1px var(--lp-line-soft);

/* 深色：同一套解剖，投影换成纯黑并提高 alpha */
--lp-shadow-sm:
    0 1px 0 rgba(0, 0, 0, 0.2), 0 4px 12px -6px rgba(0, 0, 0, 0.5),
    0 0 0 1px var(--lp-line-soft);
```

**投影必须去紫。** 原来是 `rgba(23, 20, 66, ·)`，卡片一多，紫就从阴影里渗回来，把中性底的努力整体抵消掉。全站 11 处已在 mock 中验证换成 `rgba(14, 14, 20, ·)`。

同时删除：

- `--lp-tactile-top` / `--lp-tactile-top-soft` / `--lp-tactile-ring`（铣削配方的零件，无其他消费者）
- `.landing-root .lp-product-demo / .lp-machine / .lp-feat / .lp-price-card / .lp-cta-card` 上的卡面纹理与"螺钉"伪元素（`styles.css:2314` 起、`:2405` 起、`:2426` 起）
- `.landing-root::before` 的拉丝铝背景（`styles.css:2260`）—— 它的位置由 Fieldwork 的大气层接管（§3.1 角色 A）

### 1.6 文本选中

现在没有 `::selection` 规则，浏览器默认的选中蓝会和 Iris 打架。加一条：

```css
.landing-root ::selection {
    background: var(--lp-info-bg);
    color: var(--lp-ink);
}
```

用 `-bg`（10% 透明度）而不是实色：营销页的选中往往覆盖整段，实色会把长段文字变成一条色带。

### 1.7 主按钮

保持**近黑石板**：`#0d0d10`，hover `#24252a`，前景 `#f7f7f8`。深色模式翻成近白石板：`#f2f2f4` / `#dedee1` / 前景 `#0a0a0c`。

参考图里唯一的纯黑就是按钮 —— 它是页面上最强的一击，不该让给品牌色。

## 2. 文字系统

### 2.1 两个语域

| 家族                | 何时用                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| `Fraunces Variable` | 只有 hero、分区标题、故事卡标题、大数字、引文。**≥24px 才允许出现。**                                           |
| `Geist`             | 其余一切：lead、正文、按钮、导航、标签、表头、徽章。字重只用 400 / 500。                                        |
| `Geist Mono`        | 技术信号（框架名、runtime 状态、CLI、路径、hex）、eyebrow、表格数字，外加一个新职务：**Fieldwork 的字形字体**。 |

中间没有第三种。参考图的字体逻辑很硬：所有小字是中性无衬线，所有大字是高对比细衬线。

### 2.2 字体加载

**已定：Fraunces，SOFT 50，WONK 0，字重 300（卡片标题 400）。**

```bash
pnpm --filter @manyfold/web add @fontsource-variable/fraunces
```

```css
/* styles.css 顶部，紧跟现有的 geist 导入 */
@import '@fontsource-variable/fraunces/full.css';
/* 斜体先不加载 —— 见下面的第 5 条 */
```

四个必须知道的实现细节：

1. **family 名是 `'Fraunces Variable'`，不是 `'Fraunces'`。** 写错了会静默回退到 CJK 宋体 —— 中文页面上完全看不出来，英文页面上才暴露。
2. **必须用 `full.css`，不能用 `soft.css`。** fontsource 按轴切了子集：`soft.css`（SOFT + wght）只有 140KB，比 `full.css` 的 271KB 省一半 —— 但它没有 `opsz` 轴。实测 hero 在 opsz 14（`soft.css` 的固定光学尺寸）下字面明显更宽更松，丢掉了 76px 该有的紧凑与优雅。这 131KB 买的是 hero 的字面质量，值。
3. **`opsz` 不要写死**，交给 `font-optical-sizing: auto`。这样 hero（clamp 上限 100px）自动取到高对比的 display 切，卡片标题（26px）取到笔画更稳的正文切 —— 一支字两种表现，不用手动分配。一旦在 `font-variation-settings` 里显式写 `'opsz'`，`auto` 就失效。
4. **`WONK` 必须钉 0。** 它的默认值是 0，但显式钉住，否则任何一次上游默认值变化都会让页面冒出摇摆的怪笔画。

5. **斜体暂时不加载。** 标题的强调改成实色之后（§2.5），整个 landing 只剩引文 `.lp-quote` 会用到斜体，而它目前还没有任何调用点。所以先只 `@import 'full.css'`，把字体预算从 271KB 砍到 **121KB**。真的排上引文时再加 `full-italic.css`，并在那次改动里重新量一遍首屏。

字体预算：latin 子集 normal **121KB**（加载斜体则 +150KB = 271KB）。参照系是同页的 `landing-workbench.png`（268KB）—— 现在字体只占它的不到一半。latin-ext / vietnamese 子集有独立的 `unicode-range`，只在页面真的出现那些字符时才下载。

> **后续可选优化（不在本轮）**：用 `fonttools varLib.instancer` 把 SOFT 钉死在 50、保留 opsz + wght 两轴，产出物自托管。预期 ≈150KB，省下 121KB 且渲染不变。代价是引入一个字体构建步骤。

### 2.5 强调词：一支实色，没有第二个装置

现在 `.lp-h-accent` 是一套"蚀刻金属"配方：`background-clip: text` + 线性渐变 + 两层 `drop-shadow`，在 `styles.css` 里定义了**三处**（`:2532` 浅色、`:2548` 深色、`:2898` 覆盖）。

**全部删掉，换成一条规则：**

```css
.landing-root .lp-h-accent,
.landing-root .lp-floor-accent {
    font-family: inherit;
    font-style: normal;
    color: var(--lp-info);
    /* 渐变配方的所有残留都要清掉，否则 background-clip 会让字消失 */
    background: none;
    -webkit-background-clip: initial;
    background-clip: initial;
    -webkit-text-fill-color: currentColor;
    filter: none;
}
```

**没有 `:lang()` 分支，中英文走同一条规则。** 这是实色方案最大的好处：渐变方案需要浅深两套值，斜体方案需要一条 CJK 例外（宋体没有真斜体，浏览器只会合成倾斜）——实色两样都不需要。**一个装置，一条规则，零例外。**

**标题里不使用斜体**（§2.6 T3）。斜体在大字号上不读作"重音"，读作"换了个声音在说话"——夹在一句陈述句中间会让那几个词像旁白，而不像被强调。

两条约束：

- 强调只能是**一整个短语**（1–3 个词），不能是句中的孤立单词 —— 单词染色会读成链接。
- **强调是修辞，不是信息。** 把强调色换成 `--lp-ink` 之后句子必须仍然完整可读；不允许出现"只有变色那部分才是重点"的依赖（§8 的 forced-colors 与灰度打印两行都会打掉它）。

### 2.6 六条硬规则

| #   | 规则                     | 内容                                                                                                                                                                                        |
| --- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | **24px 门槛**            | 衬线只在 ≥24px 使用。高对比衬线的细笔画在小尺寸会碎成灰渣，读起来像渲染出错。24px 以下一律 Geist。                                                                                          |
| T2  | **只有 300 / 400**       | 永远不加粗。衬线的分量来自尺寸和字面对比度，不来自字重；`font-weight: 600` 的衬线立刻从优雅掉到廉价。                                                                                       |
| T3  | **强调用实色，不用斜体** | 强调词只换成 `--lp-info`，字形保持正体。**标题里禁止斜体** —— 大字号的斜体读作"换了声音"而不是重音，而且它会逼出一条 CJK 例外。斜体只保留给引文（换声音正是它的本义）。                     |
| T4  | **禁区**                 | 按钮、导航、标签、表头、徽章、tooltip、代码、任何控件 —— 全部禁止衬线。衬线是"标题的语域"，进入控件就读成装饰字。                                                                           |
| T5  | **三明治结构**           | 一个内容块里最多一个衬线元素，固定夹在 mono/sans eyebrow ↑ 与 sans lead ↓ 之间。两个衬线标题相邻 = 语域失效。                                                                               |
| T6  | **中文即宋体**           | Display 的 CJK 回退是 `Source Han Serif SC → Noto Serif SC → Songti SC → SimSun`。宋体本身就是衬线，双语落在同一语域。但 CJK 必须 **tracking 回 0、lh 提到 1.15**，否则全角方块会挤在一起。 |

### 2.7 文案约束（排版反过来对内容提要求）

衬线 hero 有一个无衬线时代不存在的约束：**字面更宽、行数更少，所以文案的字数预算是硬的。**

| 位置                | 单行预算（en）    | 总预算       | 说明                                       |
| ------------------- | ----------------- | ------------ | ------------------------------------------ |
| `.lp-h1` 100px 满宽 | ≈18 字符          | 最多 3 行    | 超过 3 行 hero 就压掉首屏的 CTA            |
| `.lp-h2`            | ≈28 字符          | 最多 2 行    |                                            |
| `.lp-h3`            | ≈30 字符          | 最多 2 行    |                                            |
| `.lp-lead`          | `max-width: 56ch` | 最多 3 行    | 已有约束，不动                             |
| 强调词（实色）      | 1–3 个词          | 一个标题一处 | 四个词以上就不再是重音，而是把半句话染了色 |

三条规则：

- **每个 display 元素都要 `text-wrap: balance`。** 衬线的字宽差异比 Geist 大，默认换行经常留下一个孤字。
- **多语言要留 35% 余量。** 德语和俄语的同义句普遍比英语长 30–35%（`packages/i18n` 有 11 个语种）。hero 的字数预算按英语顶格写，德语就会溢出到第四行。验收时至少切 `de` 与 `ru` 各看一次。
- **不要在标题里放不可断词**（长 URL、`ProductNameWithoutSpaces`）。衬线在大字号下没有连字符，一个不可断词会直接顶破容器。

## 3. Fieldwork —— 像素 / ASCII 场

同一条规则在三个尺度上的复用：**凡是被画出来的东西，都量化到格子上。**

### 3.1 三个角色

| 角色                    | 是什么                             | 墨量天花板                                                        | 落在哪里                           |
| ----------------------- | ---------------------------------- | ----------------------------------------------------------------- | ---------------------------------- |
| **A · 大气 ATMOSPHERE** | 半调网点，由云场驱动点的大小与浓度 | 外缘峰值 ≤0.55，**内容一侧必须衰减到 ≤0.06**，且只用 `·`–`:` 两档 | 页面顶/底的带、深色 CTA 卡、footer |
| **B · 主体 SUBJECT**    | ASCII 场，八档字形 + 三张墨版      | 八档全开，但**一屏只许一个**                                      | hero、空态、大卡片、分区插图       |
| **C · 数据 DATA**       | 像素计量，格子是真实数值的量化     | α = 1.0，实心格                                                   | 用量 / 配额 / 通过率               |

跨过天花板，就从"质感"变成"噪点"。

### 3.2 墨阶字符梯

**八个字形 = 八档墨量。深浅由字符本身的覆盖率承担，不由 alpha 承担。**

```
档位   0    1    2    3    4    5    6    7
binary       ·    :    +    1    0    8    @
halftone     ·    :    o    0    O    8    @
wave         ·    :    -    ~    +    #    @
语义   空   尘   雾   细   体   重   核   实
墨版    —   浅   浅   中   中   深   深   深
```

这条是整套语言细节感的来源：只有 `0` 的场是一张噪点纸，有梯子的场才有明暗、有体积、有边缘。

三条梯子按语境选：

- **binary** —— 几何主体（环 / 球 / 折面）。保留 0/1 的数据感。
- **halftone** —— 云与大气。圆形字形接近网点。
- **wave** —— 水波。`- ~ +` 是横向笔画，顺着波纹方向。

每条梯子必须按**实际墨量**排序，不是按语义排序。同一墨阶内允许多个等价字形，选哪一个由**坐标哈希**决定 —— 稳定，不闪。

### 3.3 三张墨版

一个场只有一个色相（Iris），但按墨阶拆成**浅 / 中 / 深三张版叠印** —— 这就是印刷分色。三版让水波的波谷、波峰、液滴各自成层，画面才有纵深。

```css
.lp-field pre[data-ink='1'] {
    color: rgb(var(--lp-field) / 0.3);
}
.lp-field pre[data-ink='2'] {
    color: rgb(var(--lp-field) / 0.66);
}
.lp-field pre[data-ink='3'] {
    color: rgb(var(--lp-field-deep));
}
```

计量条的空槽用 `--lp-idle-bg`（一层墨洗），不是 `--lp-faint` —— 空槽落在四种不同的父背景上，实色只能对其中一种调准；`--lp-faint` 留给标签圆点。

禁止彩色场，禁止第四张版。

### 3.4 七条法则

| #   | 法则               | 内容                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L1  | **格律**           | 一切场都是点阵，pitch 只取 `4 / 8 / 13 / 21 / 34`（斐波那契档），单元格对齐，绝不自由落点。**网点是正方形且对齐整像素** —— 菱形读作宝石，正方形才读作像素。                                                                                                                                                                                                            |
| L2  | **字形承担墨阶**   | 每格的墨量 = 一个标量场的取值（几何 / 云密度 / 波高 / 噪声 / **真实数据**），量化到八个字形上。随机只允许决定"同一墨阶里写哪个等价字形"，且必须由坐标哈希决定 —— 每帧重掷会变成雪花屏。                                                                                                                                                                                |
| L3  | **三角色三天花板** | 见 §3.1 的表。                                                                                                                                                                                                                                                                                                                                                         |
| L4  | **单色，三张墨版** | 见 §3.3。                                                                                                                                                                                                                                                                                                                                                              |
| L5  | **必须收边**       | 每个场都以 `mask-image` 渐变结束，不许硬切。**正文永远不落在 α>0.06 的格子上。**                                                                                                                                                                                                                                                                                       |
| L6  | **无缝循环**       | 一个循环 8–24s（取 **12s**），必须逐格无缝：时间项一律写成 `sin(2π(… − n·t))` 且 **n 取整数**，`t=1` 就和 `t=0` 完全相同；有机的湍流用 `(cos 2πt, sin 2πt)` 采样噪声，也天然周期。字形场 **20fps**（ASCII 本就是机械媒介，帧率太高反而丢掉电报机质感），大气层 **8fps**。只允许整场演化，禁止逐格闪烁；数据场只在数值变化时动；`prefers-reduced-motion` 一律定格首帧。 |
| L7  | **场是内容的替身** | 产品里的主体场必须指代真实对象：agent 的身份哈希、这次运行的形状、这份数据的分布。**禁止纯装饰壁纸** —— 那是 landing 大气层才有的特权。                                                                                                                                                                                                                                |

### 3.5 形状库

主体场只有这几种，且都是"流形"：

| 形状               | 数学                                                   | 语境                                                                 |
| ------------------ | ------------------------------------------------------ | -------------------------------------------------------------------- |
| **Ripple · 水波**  | 三源干涉 + 环幅缓衰 + 泡沫核（不落墨）+ 锚定的液滴斑点 | **hero 主场**。品牌隐喻：一次输入向外传播 = _your work, multiplied_  |
| **Clouds · 云海**  | 谱合成（整数波数横向可平铺）+ 软阈值                   | 空态、分区过渡。浅色是正片（云 = 密墨），深色自动变负片（云 = 亮点） |
| **Torus · 环**     | 经典 donut，A/B 各转整一圈                             | 大卡片、加载。闭合的流形 = many folds                                |
| **Sphere · 球**    | 兰伯特光照 + 随 t 整周推移的经线带                     | "单一对象"语境：一个 runtime、一个模型、一次调用                     |
| **Fold · 折面**    | 两条谱合成折带汇聚                                     | "多路汇聚"语境：多 agent、多渠道、编排                               |
| **Drift · 噪声带** | 三谐波 + 竖向包络                                      | 唯一允许的"无意义"场，**只能当大气层用**                             |

**环频有硬上限。** 一格只能画一个字符，环距小于约 3 格就会走样成噪点。R≈22 格的网格上，波数 k ≤ 5（每环约 4.4 格）。参考图里那种越往内越密的毛细波，我们的网格分辨不出来 —— 那部分细节改由泡沫核的湍流承担。第一版把 k 开到 8.5，整片糊成雪花，这是实测踩过的坑。

外加一个纯 CSS 的分节线 `.lp-pxrule`（pitch 9 的点阵，居中最实、两端消失），只用在大分区之间。

> **knip 注意**：`fields.ts` 有测试引用所以是干净的，但四个组件 + `field.css` 在被 `Landing.tsx` import 之前会被 knip 判为 unused files（已实测）。**所以组件要和 P1 的挂载改动同一个 PR 落地**，不要为它们加 knip 豁免。

**渲染契约（这条决定了动画跑不跑得动）：** 一帧只允许**三次 `textContent` 写入** —— 三张墨版各一次。不要 span、不要内联样式、不要 per-cell DOM。收边靠 CSS `mask-image`，不靠逐格衰减。这是从"每格一个 span"改过来的，性能差一个数量级。

DOM 形状：

```html
<div class="lp-field" data-mask="radial">
    <pre data-ink="1"></pre>
    <pre data-ink="2"></pre>
    <pre data-ink="3"></pre>
</div>
```

三个 `<pre>` 用 `display: grid` + `grid-area: 1/1` 叠在一起。

### 3.7 怎么防止它腐坏

场是"看起来对不对"的东西，最容易在半年后被一次无心的重构悄悄改坏。所以不变量全部写成了可执行的断言 —— `pnpm --filter @manyfold/web test`：

| 测试                        | 拦住什么                                                                                                                                  |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **无缝循环**（六个形状）    | `t=1` 的三张墨版必须与 `t=0` **逐字节相同**。任何人往时间项里塞一个非整数频率，都会在这里失败，而不是在别人眼睛里失败。这是最重要的一条。 |
| 墨阶字符梯                  | 每条梯子必须八格、0 号是空格、**不许有重复字形**（重复 = 两个墨阶不可分辨）。                                                             |
| 墨版划分                    | 0 号不上版；1–7 各自落在三张版之一；**墨越深不许换到更浅的版**。                                                                          |
| 三版不重叠                  | 同一格永远只在一张版上有字 —— 叠印不是叠字。                                                                                              |
| 至少三个墨阶                | 直接编码 §3.2 的动机：只用一两个字形的场是一张噪点纸，不是图像。                                                                          |
| 环频上限                    | `RIPPLE_MAX_WAVENUMBER ≤ 5`。这个常量就是"整片糊成雪花"那次的墓碑。                                                                       |
| 球是圆的                    | 量墨迹包围盒的视觉长宽比，误差 <16%。删掉 `CELL_ASPECT` 校正就会红。                                                                      |
| 循环时长                    | `8s ≤ LOOP_MS ≤ 24s`。                                                                                                                    |
| 显影只减不加                | 加载脉冲必须是"淡入"，不能过曝。                                                                                                          |
| **黄金帧**                  | 24×10 的 ripple/wave 定格帧，以字面量存在测试里 —— 常量被改动会显示成一个**可读的 diff**，而不是含糊的"看起来不一样了"。                  |
| 确定性 / 网格完整性 / sigil | 同参数两次调用完全一致；每张版是完整的 cols×rows 块；印记左右镜像、逐 seed 稳定、不会出空白。                                             |

黄金帧要**有意识地**重新生成，不要为了让红测试变绿而重生成。

三件不在源码里、需要知道去哪找的东西：

1. **视觉参考稿** 是仓库根的 `.landing-iris-field-serif.preview.html`（未纳入 git 的临时文件）。P1 挂载完成、landing 上能看到真场之后，**它就该删掉** —— 留着两份会漂。删之前把它还独有的东西（三支衬线候选的对比、色板规范页）搬进本文档或截图存档。
2. **循环视频** 是产物，不是资产 —— 从代码可再生，不必进 git。管线：Playwright 逐帧调 `window.__fieldFrame(i, total)`（把这个口开在 landing 的 dev 构建上）→ 240 帧 PNG → `ffmpeg -framerate 20 -i f%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18`。验证接缝的办法是量帧差：`t=0` 与 `t=1` 之间的差应与相邻两帧的差同量级。
3. **参考图** 来自外部（水波长曝、蓝天白云半调）。它们不在仓库里，本文档 §3.5 记下了从每张图提取了什么，这样即使原图丢了，判断依据还在。

### 3.8 性能与可访问性

- **只画视口里的场。** `IntersectionObserver`（`rootMargin: 160px`）维护一个 live 集合；一页十几个 ASCII 场，全画会白烧 CPU。
- **`prefers-reduced-motion: reduce` 一律定格首帧**，不是减速。
- 场是纯装饰：容器 `aria-hidden="true"`，不进无障碍树。
- 单元格纵横比 h/w ≈ **1.36**（mono 0.6em advance + lh 0.92 + tracking 0.06em）。所有场都要按它校正，否则圆会画成椭圆。
- 字形场 20fps / 大气层 8fps 是上限，不是目标；掉帧就降 `cols`/`rows`，不要降墨阶档数。

### 3.9 进 webapp 的五个落点（本轮不做，先留接口）

组件设计成 landing 与 webapp 共用，但**本轮只在 landing 挂载**：

1. **身份印记** —— agent id 哈希出的 9×9 sigil，替代当前彩色首字母头像
2. **空态** —— 稀疏主体场 + 一行字，取代插画
3. **加载** —— 场从稀疏"显影"到完整，代替 spinner
4. **分节线** —— `.lp-pxrule` 代替 hairline
5. **计量** —— 用量 / 配额 / 通过率一律七格，不再画环形图

## 5. 组件

只列 landing 独有的、或者规则与产品不同的。没有列到的沿用现值。

**所有组件一律禁止衬线**（§2.6 T4），一律禁止裸十六进制（§9.1）。

### 5.1 按钮

三个变体，不再增加。

| 变体                | 填充               | 边                          | 文字            | 何时用               |
| ------------------- | ------------------ | --------------------------- | --------------- | -------------------- |
| `.lp-btn-primary`   | 近黑石板 `#0d0d10` | 无                          | `#f7f7f8`       | 一屏一个，主转化     |
| `.lp-btn-secondary` | `--lp-paper-warm`  | `1px var(--lp-line)`        | `--lp-ink`      | 并列的次要动作       |
| `.lp-btn-ghost`     | 透明               | hover 才出 `--lp-line-soft` | `--lp-ink-soft` | 卡内的轻动作、工具条 |

尺寸三档：**hero 44px / 默认 40px / 小 32px**；圆角一律 `--lp-r-sm`（12px），只有胶囊型导航 chip 用 `--lp-r-pill`。水平内距 = 高度的 0.45 倍取整。

深色模式主按钮**翻成近白石板**（`#f2f2f4` / 文字 `#0a0a0c`），不是变成品牌色 —— 反相的石板在深底上仍然是最强的一击，品牌色会跟场抢注意力。

状态：

| 状态          | 变化                                                                 |
| ------------- | -------------------------------------------------------------------- |
| hover         | primary → `#24252a`；secondary → `--lp-bg-soft`；ghost → 出现 1px 边 |
| active        | 再暗一档 + `transform: translateY(0.5px)`，**不许缩放**              |
| focus-visible | §6.2 的焦点环，**只在 `:focus-visible` 下出现**                      |
| disabled      | `opacity: .45`、`pointer-events: none`、光标不变形                   |
| 载入中        | 文案换成进行时（`Creating…`），**不加 spinner**（§6.4）              |

图标只允许出现在**右侧**且只允许箭头（`→`）；左侧图标位留给序号徽章（`.lp-step-cta-badge` 已在用）。

### 5.2 卡片

统一解剖：**实色填充 + 1px 边 + 单层扩散投影**。没有纹理，没有顶部内高光，没有角螺钉（§1.5 已删）。

| 尺度    | 圆角              | 阴影                | 用在                   |
| ------- | ----------------- | ------------------- | ---------------------- |
| hero 级 | `--lp-r-xl`（24） | `--lp-shadow-lg`    | hero 卡、CTA 卡        |
| 内容级  | `--lp-r-lg`（20） | `--lp-shadow-md`    | 功能卡、机器卡、定价卡 |
| 嵌套级  | `--lp-r-md`（16） | 无阴影，只有 1px 边 | 卡里的面板             |
| 迷你    | `--lp-r-sm`（12） | 无                  | 状态块、chip 容器      |

**只有可点击的卡片才有 hover**：`--lp-shadow-lg-hover` + 边线提到 `--lp-line`。静态卡片 hover 不动 —— 会动的东西必须是能点的。

同心圆角规则不变：嵌套元素的圆角 = 父级圆角 − 内距。

### 5.3 眉题 eyebrow

`--lp-mono` / 11px / 500 / `letter-spacing: .16em` / 大写 / `--lp-muted`。**保持等宽**：`01 · Hosting` 这类是坐标，属于技术信号；而且等宽小字与衬线大字的对比正好是这套系统想要的。

可选前导圆点：`--lp-info` 表示"品牌/分区"，`--lp-success` 表示"在线/实时"（唯一允许脉冲的两处之一，见 §6.3）。

### 5.4 徽章 / 状态标签

胶囊、无边、低透明度填充：`--lp-{hue}-bg` 填充 + `--lp-{hue}-strong` 文字。

**颜色永远不是唯一信号。** 每个状态标签必须同时带文字或图标 —— 色盲用户与灰度打印都要能读。

### 5.5 链接

| 位置        | 静态                                                            | hover                                |
| ----------- | --------------------------------------------------------------- | ------------------------------------ |
| 正文内联    | `--lp-info` + 下划线，`underline-offset: 2px`、`thickness: 1px` | `--lp-info-strong`，下划线加粗到 2px |
| 导航 / 页脚 | `--lp-muted`，无下划线                                          | `--lp-ink`                           |

正文内联链接**必须有下划线**。在一个只有一支强调色的系统里，颜色已经被品牌占用了，靠颜色区分链接会在灰度和低视力条件下失效。

### 5.6 导航

**不 sticky**（既有裁决）。桌面版导航**不放 CTA** —— header 不吸顶，与 hero 的 CTA 同屏重复。移动版收进 overflow 菜单。

背景与画布同色，靠一条 `--lp-line-soft` 下边线分隔；滚动时不加阴影、不加毛玻璃（页面顶部就是大气层网点，加毛玻璃会把网点糊成一团）。

语言切换与 overflow 菜单是弹层：`--lp-paper-warm` + `--lp-shadow-md`，圆角 `--lp-r-md`。

### 5.7 页脚

`--lp-bg-deep` 色带，顶部挂一条 `<Halftone edge="top">`（高度 120px，比 hero 的 220px 矮）。文字 `--lp-subtle`，链接按 §5.5 的导航档。

### 5.8 定价卡

- 价格数字用 **display 衬线**，`font-variant-numeric: lining-nums tabular-nums`（旧式数字在价格上会读错）。
- "popular" 那张卡用 **`1px var(--lp-iris-300)` 的环 + 正常阴影**，不要用彩色填充或渐变边 —— 一张被染色的卡会让另外几张看起来像被禁用了。
- 定量的额度（sandbox 数量、always-online 数量）用 `<PixelMeter>`，不用文字列表。**这是 Fieldwork 数据角色在营销页的正式落点。**
- 免费档的 0 额度是 `<PixelMeter value={0} of={7} />` —— 空槽本身就是信息。

### 5.9 FAQ 手风琴

`+` 图标展开时旋转 45° 成 `×`，180–220ms。已有的 `.lp-faq-q:focus-visible` 规则保留（这是全 landing 唯一已实现的焦点样式，别删）。展开区用 `grid-template-rows` 过渡而不是 `max-height` —— 后者需要猜一个高度。

### 5.10 表单（signup gate / access gate）

| 元素   | 规则                                                                             |
| ------ | -------------------------------------------------------------------------------- |
| 标签   | `--lp-mono` / 11px / .12em / 大写 / `--lp-subtle`                                |
| 输入框 | `--lp-paper-warm` 填充 + `1px var(--lp-line)`，圆角 `--lp-r-sm`，高 44px         |
| hover  | 边提到 `--lp-line-strong`                                                        |
| focus  | §6.2 焦点环（**这里的环不是可选项，是唯一的焦点指示**）                          |
| 错误   | 边换 `--lp-error` + 下方一行 `--lp-error` 文案。**必须有文案**，只变红是不合格的 |

### 6.1 状态矩阵

| 组件     | hover               | active            | focus-visible | disabled      |
| -------- | ------------------- | ----------------- | ------------- | ------------- |
| 按钮     | 填充降一档          | 再降 + 0.5px 下沉 | 焦点环        | `opacity .45` |
| 可点卡片 | 阴影升一档 + 边加深 | 0.5px 下沉        | 焦点环        | —             |
| 链接     | 换到 `-strong`      | —                 | 焦点环        | `--lp-subtle` |

| 手风琴   | 标题换到 `--lp-ink` | —                 | 焦点环        | —             |
| 静态卡片 | **不动**            | —                 | —             | —             |

### 6.2 焦点环 —— 有一个必须修的缺陷

产品的 `--shadow-focus` 定义成 `rgb(var(--color-focus)) 0 0 0 1px, rgb(var(--color-focus) / .18) 0 0 0 4px`，而 `--color-focus` 是 **`:root` 上的产品 token**。也就是说：**landing 换成 Iris 之后，产品那枚焦点环仍然是旧的钢蓝。**

不要在 `.landing-root` 里重新声明 `--shadow-focus`。那枚 token 每个模式只允许一份配方，并且要和 `apps/docs` 的基线成对传播；作用域内再写一份，等于让 landing 悄悄退出那份契约。landing 是手写的 `.lp-*` CSS、不走产品的 Tailwind utility，所以它自己命名这枚环：

```css
.landing-root {
    /* --lp-focus-rgb 在 §1.3 里已按模式定义好。 */
    --lp-shadow-focus:
        rgb(var(--lp-focus-rgb)) 0 0 0 1px,
        rgb(var(--lp-focus-rgb) / 0.18) 0 0 0 4px;
}

/* 近黑石板（主按钮、深色 CTA 卡）上，600 的环看不见 —— 跳到 300。 */
.landing-root .lp-btn-primary,
.landing-root .lp-cta-card {
    --lp-focus-rgb: var(--lp-iris-300-rgb);
}
```

上表里标了「焦点环」的控件用 `box-shadow: var(--lp-shadow-focus)`。**目前只有手风琴接了焦点态**（`.lp-faq-q:focus-visible` 走的是下划线替代方案），按钮、可点卡片、链接、输入框还没有接 —— 这是待补的缺口，不是设计意图。

三条硬规则：

- **只在 `:focus-visible` 下出现，永不在 `:focus` 下出现。** 仓库里有 `test/focusRingContract.test.ts` 在把这条当门禁跑，它会扫描所有 `shadow-focus` 工具类必须挂在 `focus-visible` 变体上。
- **永不 `outline: none` 而不给替代。** 键盘用户是这一页唯一没有替代路径的人群。
- **环必须在四种背景上都可见**：画布、卡面、近黑石板、深色 CTA 卡。上面那条 300 的覆盖就是为后两种。

### 6.3 运动

沿用 `DESIGN.md` §8.12 的默认值：**150–220ms，ease**。150 用于 hover 换色，200–220 用于卡片抬升与手风琴展开。

**Fieldwork 的 12s 循环不受 220ms 上限约束** —— 它不是状态过渡，是一个场在呼吸。两者是不同的东西，别混在一个预算里。

允许"活着"的东西只有三处，其余一律静止：

1. eyebrow 的前导圆点（`--lp-success` 表示在线）
2. Fieldwork 的场循环
3. 加载态的场显影（`develop`）

**禁止**：闪烁徽章、脉冲 CTA、自动播放的轮播、视差滚动、进入视口就飞入的元素超过一屏一个。

`prefers-reduced-motion: reduce` 的完整策略：

| 类别                  | reduce 下的行为                          |
| --------------------- | ---------------------------------------- |
| 所有 transition       | 时长归 0（保留终态，不是禁用状态变化）   |
| Fieldwork 场          | **定格首帧**，不是减速（已在组件里实现） |
| 大气层网点            | 定格                                     |
| `flRise` 之类入场动画 | 换成无位移的直接显示                     |
| hero 翻面             | 直接切换，不转 3D                        |

### 6.4 载入态

**营销页不用 spinner，也不用骨架屏。** landing 的内容是静态的，唯一真正异步的是价格与登录态。规则：

- 价格未到：显示占位数字的**同一字形宽度**（`tabular-nums` 已保证），不显示骨架。
- 登录态未定：CTA 显示中性文案（既有的 `GateCtaLabel` 已经在做），不闪烁。
- 任何超过 400ms 的等待才允许出现指示，且用 Fieldwork 的 `develop` 显影，不用旋转。

## 7. 响应式

### 7.1 断点

`1200`（容器上限）· `1024` · `720` · `480`。容器内距 32 / 24（≤720）/ 18（≤480），均为现值。

**≥1440 时容器不再增长**，两侧留白。大气层网点**铺满视口宽度**而不是容器宽度 —— 它是空气，不是内容。

### 7.2 Fieldwork 的每档网格 —— 这一档必须显式给

场的尺寸单位是**格**不是像素，所以它不会自动响应。每个断点一组值：

| 断点     | hero 场 | 卡片场  | 空态场  | 大气层高度 | 网点 pitch |
| -------- | ------- | ------- | ------- | ---------- | ---------- |
| ≥1024    | 58 × 29 | 38 × 15 | 52 × 16 | 220px      | 13         |
| 720–1023 | 44 × 22 | 32 × 13 | 40 × 14 | 160px      | 12         |
| < 720    | 34 × 18 | 26 × 11 | 30 × 12 | 120px      | 11         |

**低于 26 格宽，场就不再是形状而是一团噪点 —— 这时候的正确做法是整个撤掉，不是继续缩。** 具体到组件：`<AsciiField>` 在容器宽度不足时返回 `null`，而不是渲染一个 20 格的糊团。字号在小断点降到 `.lp-field-sm`（10px）。

一屏一个主体场的规则在移动端更严：**移动端整页最多两个主体场**（hero 一个，其余分区共用一个），因为竖屏滚动会让相邻两个场同时进入视口。

### 7.3 字号

`clamp()` 已经处理了缩放，但有两处例外要处理：

- **`.lp-h3` 的 ≤480px → 18px 覆盖必须删除。** 衬线的下限是 24px（T1），18px 会碎。
- **`.lp-h2` 的 ≤720px 覆盖保留但要改值**：现在是 `clamp(30px, 7vw, 44px)`，下限 30px 高于 24px 门槛，安全 —— 只需把 tracking 从 -0.035em 改到 -0.012em。

### 7.4 触摸

- 所有可点区域 ≥ **44 × 44px**。
- **不许有 hover-only 的功能**：hover 只能承载装饰性的强化，任何信息或动作都必须在无 hover 的设备上可达。
- 场是 `pointer-events: none`，不会吃掉滑动。

## 9. token 契约与变更控制

### 9.1 使用契约

1. **组件里不许出现裸十六进制、裸 rgba。** 一律走 `--lp-*`。唯一例外是遮罩里的 `#000`（它是遮罩通道，不是颜色）。
2. **不许跨语域取值**：landing 的组件不许读 `--color-*`，产品的组件不许读 `--lp-*`。§6.2 那个焦点环缺陷就是这条被破坏的产物。
3. **Fieldwork 的墨色只从 `--lp-field` / `--lp-field-deep` 取**，不要直接引 `--lp-info` —— 场的墨色和品牌色现在同值，但它们会分开演化。
4. **不许新增第四张墨版、第四条字符梯、第五种判定色**。

### 9.2 加东西的门槛

| 想加什么        | 必须同时给出                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------- |
| 一个新 `--lp-*` | 浅色值 + 深色值 + §1 里的一行 + 一个真实调用点。没有调用点的 token 不许进。                    |
| 一个新场形状    | 语义（L7：它指代什么真实对象）+ 时间项必须整数频率（测试会拦）+ §3.5 表里一行 + 一条黄金帧断言 |
| 一个新字符梯    | 八格、按真实墨量排序、无重复字形（测试会拦）+ 说明它比现有三条好在哪                           |
| 一个新组件      | 三个状态（hover / focus-visible / disabled）+ 深浅两模式 + 移动端行为                          |
| 一个新字号      | 先证明现有阶梯放不下。**衬线不许新增 24px 以下的档。**                                         |

### 9.3 改东西的门槛

- **改 token 的值**：直接改，但要跑一遍 §11 验收清单，并 grep 一遍手写的十六进制常量（色板与映射表里有手写字面量，改 token 时极易漏 —— 已经发生过一次）。
- **改一条法则（L1–L7 / T1–T6）**：要一条 ADR，放在 `oss/docs/decisions/`。这些法则互相咬合（L2 的字形梯支撑 L4 的墨版划分，L4 又支撑 L6 的性能预算），单独改一条会静默破坏另外两条。
- **重新生成黄金帧**：只在**有意**改了场的数学时做，绝不为了让红测试变绿而做。提交信息里写清改了哪个常量、为什么。
- **删一个场形状**：先确认没有调用点，再删测试里的对应断言。

### 9.4 Do / Don't

| ✅ Do                            | ❌ Don't                           |
| -------------------------------- | ---------------------------------- |
| 场在上、字在下，分层             | 正文压在主体场上                   |
| 一屏一个主体场                   | 一屏两个主体场抢注意力             |
| 强调用一支实色，中英文同一条规则 | 强调用斜体 / 彩色渐变 / 加粗衬线   |
| 颜色 + 文字双信号                | 只靠颜色表达状态                   |
| 正文链接带下划线                 | 靠品牌色区分链接                   |
| 只有可点的卡片会 hover           | 静态卡片也 hover（会动的必须能点） |
| 掉帧时降格数                     | 掉帧时降墨阶档数（直接毁掉 §3.2）  |
| 移动端撤掉太小的场               | 把场缩到 20 格继续渲染             |
| 中性底 + 单支强调色              | 底色染主题色                       |
| 网点是正方形                     | 网点是菱形（读作宝石，不读作像素） |
