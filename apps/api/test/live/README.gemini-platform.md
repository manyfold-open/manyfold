# Gemini Platform Dispatch Fixture

This opt-in fixture runs Gemini CLI 0.54.4 against a loopback Google-compatible provider inside an owned Docker container with networking disabled. It uses generated keys and fake home/workspace directories. No user daemon, external provider, or paid request is involved.

From `apps/api`, after workspace dependency builds:

```sh
RUN_GEMINI_PLATFORM_E2E=1 pnpm exec tsx test/live/gemini-platform-pricing.e2e.ts /tmp/gemini-platform-report
```

The default image is the locally retained `mf-acceptance-gemini:0.54.4` QA artifact. To build an equivalent pinned-package image on another machine, use `test/live/fixtures/gemini-tool-wire.Dockerfile` as described in [the adapter fixture guide](./README.adapter-contracts.md), then set `GEMINI_CLI_FIXTURE_IMAGE`. The report records the actual image digest and verifies the CLI version.

The fixture consumes commands generated by the production adapter. It checks fresh/resumed requests, original session context, native settings bytes, explicit/default system policies, incompatible enforced auth/model rejection, file modes, no key in settings/output, open-stdin cancellation, normal/error/cancel cleanup, and child termination. Runtime-local/profile capture asserts no platform injection.

Machine platform turns require daemon capability `exec.resources.v1`. The CLI owner allocates the private directory; the request cannot nominate a deletion path. On Windows, a fixed PowerShell supervisor assigns the suspended command to a kill-on-close Job Object before resuming it, preserves argv/stdin/stdout/exit behavior, and confirms the job is empty before final completion. The native daemon-lifecycle CI runs the owner contract on all supported OS runners under Node and Bun. Linux Docker results do not substitute for Windows native results.

Staging acceptance additionally needs the released API/CLI pair, a fixture provider/runtime, original-scope usage persistence after a reconnect, and a current managed catalog/provisioning check. Production rollout and fresh paid-provider availability probes are separate operator acceptance steps.
